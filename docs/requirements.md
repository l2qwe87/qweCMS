# Требования к проекту qweCMS

## Общее описание

qweCMS — это простая система управления контентом (CMS), предназначенная для быстрой и легкой публикации контента. Проект ориентирован на минимализм, удобство и отсутствие сложных настроек, характерных для традиционных CMS.

## Цели проекта

- Предоставить пользователям инструмент для создания и управления контентом без необходимости в глубоких технических знаниях.
- Обеспечить поддержку Markdown для написания статей и страниц.
- Гарантировать независимость от внешних облачных сервисов и маркетплейсов.
- Поддерживать открытый исходный код для сообщества.

## Функциональные требования

### 1. Управление контентом
- **Создание и редактирование контента**: Пользователь может создавать новые документы и редактировать существующие через веб-интерфейс.
- **Динамические схемы контента**: Возможность определения типов контента через JSON Schema и миксины.
- **Поддержка Markdown**: Полная поддержка синтаксиса Markdown для форматирования текста, включая заголовки, списки, ссылки, изображения и код.
- **Превью контента**: Возможность предварительного просмотра страницы перед публикацией.

### 2. Интерфейс пользователя
- **Минималистичный дизайн**: Простой и интуитивный интерфейс без лишних элементов.
- **Административный интерфейс**: Управление схемами, миксинами и контентом.
- **Навигация**: Легкая навигация между страницами и разделами.
- **Аутентификация**: Базовая система входа для администраторов (опционально).

### 3. Публикация и хранение
- **SPA архитектура**: Приложение работает как Single Page Application с динамической загрузкой контента.
- **База данных MongoDB**: Все данные хранятся в MongoDB с динамическими коллекциями для каждого типа контента.
- **Экспорт**: Возможность экспорта контента в различные форматы (HTML, PDF и т.д.).

## Нефункциональные требования

### 1. Производительность
- Быстрая загрузка страниц (менее 1 секунды для динамического контента).
- Низкое потребление ресурсов сервера.

### 2. Безопасность
- Защита от основных уязвимостей (XSS, CSRF).
- Шифрование данных при необходимости.

### 3. Совместимость
- Поддержка современных браузеров (Chrome, Firefox, Safari, Edge).
- Кросс-платформенность (Windows, Linux, macOS).

### 4. Масштабируемость
- Плагинная архитектура для расширения функционала.
- Динамические схемы контента через миксины полей.

## Технологии
- **Backend**: .NET (ASP.NET Core) для серверной части.
- **Frontend**: Angular для клиентского интерфейса.
- **База данных**: MongoDB для хранения контента и схем.
- **Markdown обработка**: Библиотека для обработки Markdown в .NET экосистеме.

## Критерии приемки
- Успешная установка и запуск проекта по инструкции из README.md.
- Создание и публикация тестовой страницы с Markdown-контентом.
- Прохождение базовых тестов на производительность и безопасность.

## Риски и ограничения
- Ограниченная поддержка мультимедиа (изображения, видео) на начальном этапе.
- Не подходит для крупных сайтов с высокой нагрузкой без доработок.
